### `src/gameworld/play/routes.py` (controller, request-response + WebSocket)

**Analog:** `src/gameworld/api/me.py`

**Modul-Docstring und Imports** (me.py Z. 1-33): Docstring nennt, warum die Route USER ist und dass die UID nur aus der signierten Anfrage kommt. Router mit Präfix, ohne `require_verwalter` (Kinder und Verwalter, D-11):

"""Routen für alle angemeldeten Konten: Selbstauskunft und eigene Welten.

Keine Verwalter-Sperre: AppAPI-Routen ^/api/me$ und ^/api/my/.* stehen in
info.xml auf USER. Jede Antwort enthält darum nur Daten des anfragenden
Kontos; die UID kommt aus der signierten AppAPI-Anfrage, nie aus dem Browser

from __future__ import annotations

import anyio.to_thread
from fastapi import APIRouter, HTTPException, status
from pydantic import BaseModel, Field

    MSG_UNAVAILABLE,

)

**Kern "nur eigenes Konto + Einladung prüfen"** (me.py Z. 130-170). Für `POST /api/my/play-ticket` genau diese Kette übernehmen: Profil aus `roles.profile(uid)`, eigene Welten aus `access.my_worlds(profile)`, Welt nur, wenn `world_id` in dieser Liste steht, Port und Status aus `service.list_worlds()`:
```python
@router.get("/my/worlds")
async def my_worlds(
    uid: UserDep, roles: RolesDep, access: AccessDep, service: ServiceDep, playtime: TimeDep
) -> MyWorldsOut:
    try:
        profile = await roles.profile(uid)
        mine = await access.my_worlds(profile)
    except (RoleUnavailableError, SecretUnavailableError):
        raise HTTPException(status.HTTP_503_SERVICE_UNAVAILABLE, detail=MSG_UNAVAILABLE) from None
    if not mine:
        return MyWorldsOut(worlds=[])
    ...
    views = {view.id: view for view in await service.list_worlds()}
    ...
    for entry in mine:
        view = views.get(entry.world_id)
        if view is None:
            continue
```
`entry` ist `MyWorld(world_id, player_name, password)` (`src/gameworld/access/service.py` Z. 112-118, gebaut in `_my_worlds_sync` Z. 602-610). Das liefert Spielername und Passwort für Ticket und Variante A/B, ohne neuen Zugriffspfad: `derive_password` läuft dort bereits für genau `profile.user_id`.

**Welt-ID-Validierung:** `WorldId = Annotated[str, Path(pattern="^[0-9a-f]{12}$")]` aus `src/gameworld/api/worlds.py` Z. 206. Für den JSON-Body als Pydantic-Feld mit demselben Muster und `model_config = ConfigDict(extra="forbid")` wie `InviteRequest` in `src/gameworld/api/invites.py` Z. 93-97:
```python
class InviteRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    kind: Literal["user", "group"]
    target: Annotated[str, Field(max_length=64), AfterValidator(_clean_target)]
```

**Fehlerbild:** 503 mit `MSG_UNAVAILABLE` bei Nextcloud-Störung (me.py Z. 137-138), 403/404 bei nicht eingeladen. Deutsche, kindgerechte Texte als Modulkonstanten (Muster `TEXT_WELT_PROBLEM`, me.py Z. 39).

**Antwortmodell:** Wie `MyWorldOut` (me.py Z. 58-75) mit Kommentar je Feld; das Passwort nur in Variante B und nur für das eigene Konto (Kommentar "Nur das eigene Passwort, pro Anfrage aus dem Geheimnis abgeleitet", Z. 70-71).

**Verwalter frei von Spielzeit (D-11):** Muster `exempt=role_of(profile) == ROLE_VERWALTER` (me.py Z. 178). Der Proxy selbst prüft Spielzeit nicht (D-02), das Muster ist nur relevant, falls das Ticket die Rolle mitführt.

**WebSocket-Endpunkt:** kein Analog im Repo. Skizze in RESEARCH "WS-Endpunkt (Skizze, Prüfreihenfolge wichtig)" (Z. 450-476) verwenden. Projektbezogene Pflichtpunkte:
- `JsonOnlyChangesMiddleware` greift **nicht** für WebSockets: `refusal()` gibt bei `scope["type"] != "http"` sofort `None` zurück (`src/gameworld/api/csrf.py` Z. 44). Die Origin-Prüfung (CSWSH) muss darum im WS-Handler selbst stehen, als reine Funktion nach dem Muster `refusal(scope) -> str | None` (csrf.py Z. 42-53), damit sie ohne Server testbar ist.
- `AppAPIAuthMiddleware` prüft auch `websocket`-Scopes (`.venv/Lib/site-packages/nc_py_api/ex_app/integration_fastapi.py` Z. 358-374) und setzt `scope["username"]`. Unter HaRP liefert `current_user` (roles.py Z. 92-97) die UID; für den WS das Gegenstück auf `WebSocket.scope.get("username")` bauen (kein `Request`).
- Achtung: Bei fehlgeschlagener Signatur sendet die Middleware eine `PlainTextResponse` (Z. 376-378) auch an einen WS-Scope. Im Dev-Weg (Dev-Front, kein AppAPI-Header) muss die Spielroute deshalb in `disable_for` stehen (fnmatch auf den Pfad ohne führenden `/`, Z. 355-366), Auth dann allein über Ticket (RESEARCH Pattern 2).

**Statische Spielroute (`GET /play/*`):** Analog nur teilweise: nc_py_api mountet `js`, `l10n`, `css`, `img` per `StaticFiles` (integration_fastapi.py Z. 183-190, aufgerufen über `set_handlers` in `main.py` Z. 56). Für die Spielroute eigene Auslieferung mit festen Headern (COOP/COEP/CORP/CSP/Permissions-Policy/Referrer-Policy, `application/wasm`) aus RESEARCH Pattern 3. Wichtig:
- **Nicht nach `js/` legen:** `frontend/vite.config.js` Z. 27-30 setzt `emptyOutDir: true` auf `../js`, jeder Frontend-Build löscht dort alles.
- `map_app_static` sucht relativ zu `os.getcwd()` (Repo-Root, siehe Kommentar `main.py` Z. 54-55). Ein eigenes Verzeichnis (etwa `play/` oder `.dev/luanti-wasm-www/`) analog per Pfad relativ zum cwd auflösen, ausserhalb des Store-Images.

### `src/gameworld/play/mtp.py` (utility rein, transform)

**Analog:** `tests/e2e/luanti_probe.py` `Probe.handle` (Z. 140-154) und Konstanten (Z. 35-52)
```python
def handle(self, channel: int, body: bytes) -> tuple[int, bytes] | None:
    """Verarbeitet ein Paket; liefert (Kommando, Daten) bei einem Nutzpaket."""
    ptype = body[0]
    if ptype == 3:  # RELIABLE
        seq = struct.unpack(">H", body[1:3])[0]
        self.send_raw(channel, struct.pack(">BBH", 0, 0, seq))  # ACK
        return self.handle(channel, body[3:])
    if ptype == 0:  # CONTROL
        if body[1] == 1:  # SET_PEER_ID
            self.peer_id = struct.unpack(">H", body[2:4])[0]
        return None
    if ptype == 1:  # ORIGINAL
        command = struct.unpack(">H", body[1:3])[0]
        return command, body[3:]
    return None  # SPLIT kommt bei Init und SRP nicht vor
```
Für den Proxy als **reine** Funktion ohne Socket (kein ACK senden, nur parsen): `parse(datagram) -> Parsed(channel, reliable_seq | None, command | None, payload)`. Kommando-IDs aus luanti_probe übernehmen: `TOSERVER_INIT 0x02`, `TOSERVER_SRP_BYTES_A 0x51`, `TOSERVER_SRP_BYTES_M 0x52`, `TOCLIENT_SRP_BYTES_S_B 0x60` (Z. 229), `AUTH_ACCEPT 0x03`, `ACCESS_DENIED 0x0A`, dazu `TOSERVER_FIRST_SRP 0x50` (immer verwerfen). INIT-Layout zum Namen lesen (luanti_probe Z. 190): `struct.pack(">BH", 29, 0) + struct.pack(">HH", 37, 53) + _str16(name)`, also Name ab Offset 7 als `u16`-Länge + Bytes. Parse-Fehler heißt Sitzung beenden (RESEARCH Pattern 4).

### `src/gameworld/play/srp_proxy.py` (Variante A, Krypto)

**Analog:** `tests/e2e/luanti_probe.py` `SrpClient` (Z. 55-96), gegen echten 5.17.0-Server bewährt
```python
class SrpClient:
    """Client-Seite von SRP-6a, wie Luanti sie erwartet."""

    def __init__(self, name: str, password: str) -> None:
        self.name = name  # Originalschreibweise für M, kleingeschrieben nur in x
        self.password = password
        self.secret = secrets.randbits(256)
        self.public = pow(G, self.secret, N)

    def bytes_a(self) -> bytes:
        return _bin(self.public)

    def process(self, salt: bytes, bytes_b: bytes) -> bytes:
        server_public = int.from_bytes(bytes_b, "big")
        u = _h_nn(self.public, server_public)
        x = _x(salt, self.name, self.password)
        k = _h_nn(N, G)
        shared = pow((server_public - k * pow(G, x, N)) % N, self.secret + u * x, N)
        key = _h(_bin(shared))
        h_xor = bytes(i ^ j for i, j in zip(_h(_bin(N)), _h(_bin(G)), strict=True))
        return _h(h_xor, _h(self.name.encode("utf-8")), salt, _bin(self.public), _bin(server_public), key)
```
`N`, `G` aus `gameworld.provisioner.luanti_auth` importieren (luanti_probe Z. 33), nie neu definieren. Bei Übernahme in `src/` die Hilfsfunktionen `_bin`, `_h`, `_x`, `_h_nn` mitnehmen und luanti_probe danach auf das src-Modul zeigen lassen (eine Wahrheit). Paketformat SRP_BYTES_A (luanti_probe Z. 202): `_str16(bytes_a) + b"\x01"`; S_B parsen wie Z. 208-211; SRP_BYTES_M Z. 212.

### `appinfo/info.xml` und `tests/test_info_xml.py` (ändern)

**Analog:** info.xml Z. 59-96 und Kommentar Z. 7-18 ("Reihenfolge ist Semantik", "^/api/me$ auf $").

**Befund für den Planner:** `^/api/my/.*` ist nur für `GET` als USER freigegeben (Z. 78-83). Ein `POST /api/my/play-ticket` fiele auf das ADMIN-Auffangmuster `^/api/.*` (Z. 90-95) und wäre für Kinder gesperrt. Nötig ist eine eigene Route vor dem ADMIN-Muster:
```xml
<route>
	<url>^/api/my/play-ticket$</url>
	<verb>POST</verb>
	<access_level>USER</access_level>
	<headers_to_exclude>[]</headers_to_exclude>
</route>
```
dazu `^/play/.*` (GET, USER) für Seite, Assets und WS-Upgrade (HaRP prüft die Route auch beim Upgrade, RESEARCH "HaRP: Identität am WS").

`tests/test_info_xml.py` erzwingt die Liste exakt (`EXPECTED_ROUTES`, Z. 47-49), Anker für USER-API-Routen (Z. 52-56) und genau ein ADMIN-Muster am Ende (Z. 66-70). EXPECTED_ROUTES mitziehen; die neue Route endet auf `$`, passt also zur Regel in Z. 55-56.
