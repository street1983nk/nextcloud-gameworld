## Phase Goal

**As a** Elternteil, **I want to** für jedes Kind Spielzeiten mit Wochenplan, Ferienregeln und Zeitfenstern pro Welt festlegen, **so that** ich mich darauf verlassen kann, dass der Server sie durchsetzt, auch nach Welt-Neustart und Rejoin.

<objective>
Kind-Ansicht mit Restzeit: Kinder sehen vorab, wie lange sie heute noch spielen dürfen und wann die nächste Spielzeit beginnt, und ob eine Welt gerade offen ist. Das vermeidet Frust vor dem Join; durchgesetzt wird weiterhin nur im Spielserver. Nach diesem Plan ist die Phase funktional vollständig; die Abnahme folgt in 04-08.

Purpose: Kindgerechte Transparenz statt überraschender Trennung; Datensparsamkeit (nur eigene Werte).
Output: GET /api/my/playtime, erweiterte /api/my/worlds, PlaytimeCard, Fenster-Hinweis in ConnectionCard.

Entscheide (Claude's Discretion, dokumentiert):
- Die API liefert Struktur, der Browser formuliert: {limited, state ("ok" | "aufgebraucht" | "fenster" | "tag"), remaining_minutes (abgerundet, null ohne Limit), until_minute (lokal, Minuten ab 00:00, null = Tagesende), next {weekday, minute} | null}. Rest unter 60 s -> state "aufgebraucht" bzw. "fenster" (gleiche Schwelle wie MIN_LEFT).
- /api/my/worlds bekommt je Welt window_open (bool | null, null = kein Fenster) und window_next {weekday, start, end} | null (aktuelles oder nächstes Öffnungsfenster); keine vollständigen Wochenpläne.
- info.xml bleibt unverändert: ^/api/my/.* ist bereits USER mit GET.
</objective>
