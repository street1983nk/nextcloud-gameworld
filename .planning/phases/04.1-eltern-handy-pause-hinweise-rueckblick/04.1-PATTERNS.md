**Analog:** `src/gameworld/provisioner/time_mod.py` `parse_ledger` (672-699) und `src/gameworld/playtime/ledger.py` `increments` (30-38)

**Kernmuster Parsen** (time_mod.py 679-699): ASCII mit `replace`, letzte Leerzeile weg, Kopf und `end` Pflicht, ungültige Zeilen still überspringen, jeder Name gegen `PLAYER_NAME`:
```python

        text = content.decode("ascii")
    except UnicodeDecodeError:
        text = content.decode("ascii", "replace")
    lines = text.split("\n")
    if lines and lines[-1] == "":
        lines.pop()
    if len(lines) < 2 or lines[-1] != "end":

        if match is None or not PLAYER_NAME.fullmatch(match.group(1)):
```

**Cursor-Logik (Erstkontakt und Rücksprung nur verankern)** (ledger.py Docstring 7-14, Code 30-38). Für Ereignisse: kein Cursor = nur verankern; `letzte Sequenz < Cursor` = neu verankern, nichts melden (RESEARCH Pitfall 6):
```python
def increments(seen: dict[str, int], current: dict[str, int]) -> tuple[dict[str, int], dict[str, int]]:
    """(Zuwachs je Name, neuer gesehener Stand). Rücksprung und Erstkontakt nur verankern."""
    seen_by_fold = {name.casefold(): value for name, value in seen.items()}
    delta: dict[str, int] = {}
    for name, value in current.items():
        before = seen_by_fold.get(name.casefold())
        if before is not None and value > before:
            delta[name] = value - before
    return delta, dict(current)
```
Konkreter Code-Vorschlag: RESEARCH.md "Ereignisdatei parsen" (Zeilen 421-453) folgt genau diesem Muster. Konstanten `EVENTS_FILE_NAME`, `EVENTS_FILE` gehören in `access_mod.py` (wie `STATE_FILE_NAME`/`STATE_FILE`, access_mod.py 42-46), nicht in `events/`.

```python
        if started is None:
            return False
        return written is None or written < started
```

### Verwalter-Sperre (doppelt)

**Source:** `src/gameworld/worlds/service.py` 300-322, `playtime/service.py` Docstring 21-26
**Apply to:** Takt-Erweiterung, Pause, Talk, Notify
